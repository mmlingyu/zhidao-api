# 知岛 · 知识卡片体系与年级适配方案

> 本文说明三件事：**怎么定义「新知识」和「已掌握」**、**怎么用知识卡片包呈现给家长**、
> **怎么按孩子的年龄给视觉／听觉／心理反馈，并让生成内容适配年级**。
> 同时给出落到代码里的实现方式、接口、数据结构与验证结果。

---

## 一、先确定一个判断标准

家长打开知识库时真正想问的不是「系统给他讲过几课」，而是：

> **我孩子到底会不会？哪些还差一点？**

所以本项目把「学过」和「掌握」彻底分开：

| 概念 | 错误定义 | 本项目采用的定义 |
|---|---|---|
| 新知识 | 系统还没生成过这个知识点 | 目录里有，但孩子**没有任何学习证据** |
| 学过 | 打开过讲解页 | 有接触证据（听讲解、朗读、追问） |
| 已掌握 | 看过讲解 / 答对一次 | **连续两次以上独立答对**，且未超出遗忘窗口 |
| 需巩固 | 不存在这个状态 | 曾经掌握，但按遗忘曲线回落了 |

关键取舍有三条：

1. **浏览量不参与判定。** 听十遍讲解不等于会，只给很低的「接触」权重，且接触类证据合计封顶 0.3。
2. **一次答对不算掌握。** 需要 `minCorrect = 2` 且「连续正确」也 ≥ 2，防止蒙对一次就被贴上标签。
3. **掌握不是永久勋章。** 距最后一次正确超过 21 天，掌握度按半衰期指数衰减；跌破 0.45 就从「已掌握」退回「需巩固」。这让标签保持可信，也自然产生复习任务。

## 二、四态判定模型与证据体系

### 2.1 状态机

```
新知识 ──听讲解──> 学习中 ──连续答对≥2──> 已掌握
                      ↑                      │
                      └────── 21 天未复习 ───┘ → 需巩固 →（再练一次）→ 学习中
```

| 状态 | 用户看到的文案 | 判定条件 |
|---|---|---|
| `new` 新知识 | 还没开始 | 无任何证据 |
| `learning` 学习中 | 学过，还要再练 | 有证据但掌握度 < 0.62，或正确次数不足 |
| `mastered` 已掌握 | 能独立做对 | 掌握度 ≥ 0.62 且正确次数 ≥ 2 且连续正确 ≥ 2 |
| `review` 需巩固 | 以前会，现在生疏了 | 曾掌握，衰减后掌握度 < 0.45 |

### 2.2 学习证据类型

| 类型 | 触发位置 | 权重 | 说明 |
|---|---|---|---|
| `lesson` | 打开一节课 | 0.12 | 接触，权重最低 |
| `correct` | 英语练习答对 | 0.34 | 主要掌握证据 |
| `wrong` | 英语练习答错 | 0.05 | 打断连续正确，并施加惩罚 |
| `created` | 语文仿写达标 / 数学走通思路 / 完成挑战 | 0.30 | 独立输出，比「听懂」更强 |
| `asked` | 主动追问 | 0.10 | 参与度证据 |
| `recited` | 点朗读 | 0.09 | 参与度证据 |

**接触类证据（lesson / asked / recited）单独封顶 0.3**，不会把掌握度刷满。

时间维度也参与计算：正确证据距当前超过 14 天，其贡献按 `0.5^(超出天数/21)` 衰减；
即「半年前答对过」不能和「今天刚答对」等价。

### 2.3 家长的人工裁决

系统只看得到 App 内的行为。孩子在纸上、课堂上、生活里学会的东西系统看不见，
所以家长必须拥有最终裁决权：

- 卡片背面有「我确认他掌握了」和「还需练习」两个按钮；
- 人工确认写成卡片上的显式字段 `manualMastered / manualMasteredAt`，**优先于自动判定**；
  （早期实现靠临时塞一条证据，结果 `listCards()` 每次重算时用「连续正确次数」把家长的确认悄悄推翻，已修正）
- 人工确认有 21 天有效期，过期自动释放，让遗忘规律重新接管 —— 家长说「他会了」是可信的，但半年后确实可能忘了；
- 家长确认后孩子又答错，立即释放人工覆盖，让真实表现说话。

## 三、知识卡片包怎么呈现给家长

### 3.1 三个问题 → 四个卡片包

家长看板不按学科分类，而是按**「我现在要做什么」**组织：

| 卡片包 | 回答的问题 | 排序 |
|---|---|---|
| 需要巩固 | 哪里退步了、今晚该复习什么 | 1（最需要行动） |
| 已掌握 | 孩子稳稳拿下了什么 | 2（成就） |
| 正在学 | 学过但还没吃透 | 3 |
| 还没开始 | 课标里还有哪些空白 | 4 |

顶部是四个指标：卡片总数、已掌握数、需巩固数、掌握率（分母是**学过的**而非总卡片数，避免目录越大掌握率越难看）。

### 3.2 卡片正反面

- **正面**：学科色点、状态徽章、知识点名称、判定理由（如「连续答对 2 次」）、掌握度环、最近学习日期、答对次数。
- **背面**：最近 4 条证据时间线（什么时候听过讲解、什么时候答对、什么时候答错），以及家长的两个裁决按钮。

卡片用 3D 翻转，点击时有一声轻「哒」的音效。

### 3.3 目录对账：让「新知识」不只是历史遗留

只看历史卡片，家长永远不知道孩子知识地图上还有哪些空白。
因此新增按年级/学科组织的课标目录（`curriculum.js`，三个学科共 60+ 条目），
看板底部列出**该年级还没碰过的知识点**，点击即可直接带着这个知识点去生成讲解。

用户口语化输入（如「一元一次方程怎么解」）会通过关键词打分匹配回目录条目，
保证「学过的」和「待学的」能对上账，不会生成一张孤立卡片。

## 四、面向孩子与青少年的三层交互反馈

孩子的学习动力不来自分数，而来自**「我变强了」这件事被看见**。三层同时工作，缺一层就会失效。

### 4.1 视觉层：立刻可感，无需阅读

- 答对：按钮弹一下 + 泛光（`zf-pop`），顶部飘字；
- 答错：轻晃（`zf-shake`），**不用红叉、不用刺眼警示**；
- 掌握达成：从卡片中心散出 14 个光点（`burst`）+ 卡片翻面点亮；
- 掌握度环增长动画。

要求在 0.1 秒内响应，否则孩子会以为没点到。全部用 `transform / opacity` 驱动，不触发布局。

### 4.2 听觉层：Web Audio 实时合成，不依赖音频文件

| 事件 | 声音设计 |
|---|---|
| 答对 | 上行双音；连击每 3 次升一个半音，形成「越对越脆」的爽感 |
| 每 5 连击 | 追加一层上行三音，作为「破纪录」标记 |
| 答错 | 低沉柔和两音（330Hz → 247Hz），**不是惩罚音** |
| 掌握 | 四音琶音，像解锁 |
| 卡片翻面 | 轻短一声 |

- 用 `AudioContext` + 指数衰减包络合成，起音快、收尾柔，避免「哔」的刺耳感；
- 浏览器要求用户手势后才能启动音频，首次点击时 `unlock()`；
- 按学科换音色（语文 triangle、英语/数学 sine）；
- 音量可由年级画像自动调整，也支持静音。

### 4.3 心理层：最关键，也最容易做错

| 原则 | 具体做法 |
|---|---|
| 归因于过程而非天赋 | 说「你换了三种解法，这比一次做对更有价值」，不说「你真聪明」。天赋归因会让孩子回避难题——一旦做不出，「聪明」的标签就成了威胁 |
| 答错不制造挫败 | 文案是「差一点点，再想想」「再想一步」，连击**不清零** |
| 中断连击不惩罚 | 说「今天先歇一歇，休息也是学习的一部分」，不说「连击断了」 |
| 掌握宣告指向能力成长 | 说「这个知识点你拿下了」，不说「你很棒」 |
| 不公开比较 | 孩子端没有排名、没有「落后于同学」，掌握率只给家长看 |

### 4.4 年龄差异：青少年最忌讳被当小孩哄

`feedback.js` 内置两套语气量表，按年级自动切换：

| | 小学生（`child`） | 初中及以上（`teen`） |
|---|---|---|
| 答对 | 「答对啦！」「漂亮！」 | 「对」「就是这个思路」 |
| 答错 | 「差一点点，再想想～」 | 「再想一步」「差在细节上」 |
| 掌握 | 「太棒了，又拿下一个！」 | 「这个可以算你的了」「掌握确认」 |
| 庆祝强度 | 高（满屏光点） | 低（淡化）／高中无（仅极轻飘字） |

给初中生发「太棒啦小宝贝」是**负向激励**，会直接让他关掉页面。
所以青少年期用克制、平等、就事论事的语气，并把视觉庆祝强度降到最低。

## 五、按年级适配生成内容与交互形态

### 5.1 五个认知阶段（前后端共用同一份标尺）

`grade-profile.js` 同时被 Node 端（生成提示词）和浏览器端（界面形态）引用，
避免「给一年级讲函数视角，却配了满屏大按钮」的错位。

| 阶段 | 年级 | 认知特点 | 生成约束 | 界面形态 |
|---|---|---|---|---|
| `early` 启蒙期 | 学前～二年级 | 只靠具体事物理解，一次只能处理一个任务 | 每句 ≤12 字，只用小猫/糖果/分饼干举例，禁止抽象术语、公式、多解比较 | 1 张/屏，字号 ×1.18，大按钮（≥52px），隐藏公式/多解切换/挑战/追问/进度面板，朗读优先 |
| `primary` 基础期 | 三～四年级 | 能接受简单类比，开始理解规则 | 每句 ≤20 字，校园家庭场景，允许两种做法但各配例子 | 2 张/屏，保留朗读与分步，隐藏进阶辨析 |
| `upper` 过渡期 | 五～六年级 | 能谈关系和结构，仍要例子托底 | 可讲来龙去脉与多解比较，抽象说法后紧跟具体例子 | 3 张/屏，完整练习 |
| `teen` 青少年期 | 初一～初三 | 抽象推理、在意被尊重、厌恶幼稚化 | 术语准确、逻辑完整、讲结构与迁移条件；**显式禁止**叠词/「小朋友」/空泛夸奖 | 4 张/屏，密度高，IP 气泡隐藏，圆角收敛 |
| `senior` 成熟期 | 高一～高三 | 完整抽象，把界面当工具 | 按高考学科标准，信息密度高，无鼓励语、无铺垫 | 4 张/屏，IP 挂件完全隐藏，反馈极简 |

### 5.2 生成侧实现

`models.js` 的 `buildLessonPrompt(subject, input, generation, grade)` 在 system 末尾注入
`【学习者年级适配 · 最高优先级】`，明确年级要求与通用描述冲突时以年级为准，
**但 JSON 字段结构与各项数量要求保持不变**。

这个约束很重要：展示侧可以按年级裁剪模块，生成侧结构必须稳定，
否则缓存、校验、自愈三条链路都要为年级分叉，复杂度会失控。

追问 `/api/followup` 同样注入年级约束 —— 给一年级讲主讲、用高中语气回答追问会割裂。

### 5.3 年级来源与优先级

`resolveLearner()`：

1. 请求显式 `grade`（家长为孩子切换 / 游客自选）；
2. 登录学生自己的 `grade`（**孩子登录后自动适配，无需手动选**）；
3. 家长账号或游客无年级 → 通用讲解，不做幼态化假设。

家长账号不自动套用孩子年级：家长可能是在预览或备课，把成人界面突然切成大按钮低龄版反而是干扰。

前端顶栏有年级选择器，切换后：
- 清空浏览器课程缓存；
- 触发 `zhidao:learnerrefresh`，用 `startLesson(true)` 按新年级重新生成当前课程；
- 同步反馈语气与音量。

### 5.4 缓存隔离（最容易漏掉的一环）

同一道题，一年级和初三讲的是两种课。年级必须进入**每一层**缓存键：

| 层 | 处理 |
|---|---|
| 服务端课程缓存 | `hash(... learnerStage)` |
| 服务端追问缓存 | `hash(... learnerStage)` |
| 浏览器 L0 缓存 | `tutorCacheKey() = stage + ':' + normalizeTopic()` |

已实测：同一输入 `grade1` 与 `grade9` 缓存键不同、互不命中；同年级第二次请求正常命中缓存且回显阶段正确。

### 5.5 展示侧实现

`learner.js` 把画像落到 `<html>` 上：

```
data-stage="early"  data-density="sparse"  data-tone="child"
data-celebration="high"  data-gesture="tap"
--zd-stage-font / --zd-stage-cards / --zd-mascot-amp
```

`knowledge.css` 用属性选择器统一改变字号、列数、按钮尺寸、模块显隐与反馈强度。
组件本身不需要知道年级，新增阶段只需加一组 CSS 规则。

### 6.3 数据流

```
孩子学习动作（答题/仿写/朗读/追问/看完讲解）
   │
   ├─> ZHIDAO_FEEDBACK.correct / wrong / mastered     视觉 + 听觉 + 心理（本地即时）
   │
   └─> POST /api/cards/record  ──> cards.js ──> knowledge.applyEvidence ──> Redis / JSON
                                                    │
家长看板 GET /api/cards/board <── buildPacks <── evaluateCard（每次读取重算遗忘）
   │
   └─> 卡片墙（四包 + 掌握率 + 目录空白） ──> 家长裁决 POST /api/cards/:id/mark
```

年级链路：

```
顶栏选择 / 登录学生年级
   └─> LEARNER.grade() ──> /api/tutor { grade } ──> resolveLearner ──> promptForGrade
                                    │                        │
                                    ├─> 缓存键带 stage        └─> 生成内容按年级分层
                                    └─> 响应回显 learner.profile ──> <html data-stage> ──> CSS 形态
```

### 6.4 API

| 接口 | 方法 | 权限 | 说明 |
|---|---|---|---|
| `/api/grades` | GET | 公开 | 年级表 + 五阶段摘要 |
| `/api/learner/profile?grade=` | GET | 公开 | 单年级画像 |
| `/api/cards/board?member=&grade=&subject=` | GET | 登录 | 家长看板；家长可看家庭内任一成员，学生只能看自己 |
| `/api/cards/record` | POST | 登录 | 上报学习证据；家长代记时校验成员属于本家庭 |
| `/api/cards/:id/mark` | POST | 登录 | 家长手动标记掌握 / 需练习 |
| `/api/tutor` | POST | 限流 | 新增可选 `grade`，响应新增 `learner` |
| `/api/followup` | POST | 限流 | 新增可选 `grade` |

权限实测：未登录看板 401；家长指定外部成员写入 403。

### 6.5 存储

卡片仓库与用户体系同构，复用 `UserRepository`：
`RedisCardStore`（发布时切腾讯云 Redis）优先，`LocalCardStore` 本地 JSON 兜底，
原子写（临时文件 + rename），重启不丢数据。键格式 `cards:<memberId>:<cardId>`，
天然按孩子隔离。单卡最多保留 60 条证据。

## 七、关键取舍与已知限制

1. **生成结构不随年级变**，只变内容深度；界面按年级裁剪。代价是低龄孩子的课程数据里仍有「顶流方法」等字段（只是不显示），好处是缓存/校验/自愈链路不需要分叉。
2. **家长人工确认有 21 天有效期**，不是永久。这是「尊重家长判断」与「承认遗忘规律」之间的折中。
3. **掌握判定只用 App 内证据**，无法覆盖线下学习，因此必须保留家长裁决入口。
4. **音效需用户手势解锁**，首次点击前不会有声音；静音状态存 `localStorage`。
5. **音频与动画尊重 `prefers-reduced-motion`**；前庭敏感用户会看到静态反馈。
6. 公网发布前仍建议补邮箱/短信验证；手机通过局域网 IP 使用摄像头仍需 HTTPS。

## 十、栏目级操作提示（2026-11-11 修复实录）

### 问题

用户反馈「诗文与名句」只有标题和「朗读」按钮，正文一片空白，但点朗读能读出句子。
根因：上一版年级适配把内容型模块也当作「超出认知负荷的辅助模块」收起了——

```css
/* 修复前 */
html[data-stage="early"] .poem-list,
html[data-stage="early"] .practice-input,
html[data-stage="early"] .filter-pills { display: none; }
```

朗读按钮的 `data-speak` 与诗句同源，所以数据一直在，只是被 CSS 藏了：**有声无字**。
同一处还用 `::after` 伪元素硬编码了一句提示，切换年级不会变，读屏软件也读不到。

### 修复原则

**年龄适配改变「怎么做」，不删除「学什么」。** 内容型模块（诗句、输入框、筛选器）一律不隐藏；
只收起真正抽象/比较类的辅助模块（多方法切换、公式块、变式挑战、进阶辨析等）。

### 实现

在 `grade-profile.js` 新增 `HINTS` / `GENERIC_HINTS` 与 `hintForGrade()` / `lessonFieldPrompt()`，
每个阶段给出两套文案：给孩子看的 `text / title / button / placeholder / minLength`，
和注入模型提示词的 `rule`。同一份标尺同时作用于生成侧与展示侧。

| 阶段 | 诗文与名句怎么做 | 试着写一句怎么做 | 完成门槛 |
| --- | --- | --- | --- |
| 启蒙期 | 点右边的小喇叭，听一句，跟着读一句 | 「说一句」→「我说好啦」，可请家长代打 | 说出来即可 |
| 基础期 | 先听一遍，再挑一句读给自己听 | 写一句有动作或画面的话 | 12 字 |
| 过渡期 | 想想诗人用哪个词让画面动起来 | 仿写并写出动作、神情或环境 | 16 字 |
| 青少年期 | 对照表达手法，标出关键一处 | 「迁移仿写」→「提交并自检」+ 手法说明 | 20 字 |
| 成熟期 | 从意象、句法或语体角度核对 | 迁移仿写并自检结构与语体 | 20 字 |

青少年文案显式排除「小朋友 / 宝贝 / 太棒啦 / 爸爸妈妈 / ！」，与 `feedback.js` 的 teen 语气一致。

改动落在：`grade-profile.js`（提示表与生成侧约束）、`models.js`（`buildLessonPrompt` 注入
`【语文栏目年级适配】`，不覆盖数量硬约束）、`learner.js`（暴露 `hint()`、身份变化时通知重渲染）、
`dynamic.js`（真实文本提示条、单句点读、空态兜底、按 `minLength` 判定完成、
监听 `learnerrefresh`）、`knowledge.css`（`.stage-hint` / `.poem-read`、移除内容隐藏与伪元素提示）。

### 验证

`npm run test:knowledge` 46/46；真实浏览器（Edge + MOCK 服务）11/11 断言通过：
一年级与初二诗句均可见、输入框可见、提示条随年级切换、单句朗读按钮与诗句一一对应、
整体朗读文本与可见正文同源；不刷新页面直接切年级，提示与栏目标题立即从
「听一句读一句 / 说一句」变为「对照表达手法 / 迁移仿写」。

### 教训

这次 bug 的本质是**生成侧与展示侧用了两套标准**——模型按课标给了诗句，CSS 按年级把它藏了。
文档 [A2UI-KNOWLEDGE-UI.md](A2UI-KNOWLEDGE-UI.md) 提出用 A2UI 的 catalog 能力协商把两者合并：
renderer 先声明本年级允许哪些组件，服务端就不会生成不允许的组件，从协议层杜绝「生成了却不给看」。
