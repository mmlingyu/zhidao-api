# 移动端适配方案

知岛当前的形态是「响应式 Web 应用」。本文说明**现状已做到什么**、**移动端真实的技术约束**，
以及**后续做原生 App / 小程序时的路线选择**。

---

## 一、现状：响应式 Web 已覆盖的能力

| 能力 | 状态 | 说明 |
|---|---|---|
| 布局响应式 | ✅ | 850px 折叠侧边栏 → 650px 紧凑布局 → 390px 单列 |
| 触摸友好 | ✅ | 移动端主要按钮触达区 ≥ 40px（`pwa.css` 中 `.start-button` / `.id-entry` / `.soft-button` 等） |
| 刘海屏适配 | ✅ | `env(safe-area-inset-*)` 应用于顶栏、侧边栏、页面底部、IP 挂件与 Toast（`pwa.css`） |
| 摄像头采集 | ✅ | `playsinline` + `muted`（iOS Safari 必需），`facingMode: 'user'` 前置摄像头 |
| PWA 安装 | ✅ | `manifest.webmanifest` + `sw.js`，可「添加到主屏幕」并离线打开界面 |
| 安装引导 | ✅ | 窄屏顶部提示条：有安装事件时「立即安装」，否则给出各平台手动添加步骤（`pwa.js`） |
| 版本更新提示 | ✅ | Service Worker 更新后提示刷新，不静默替换用户正在看的页面 |
| 离线外壳 | ✅ | Service Worker 预缓存应用外壳；API 始终走网络（讲解需实时模型） |
| 人脸模型离线 | ✅ | 模型与 wasm 随应用缓存，不依赖 CDN |
| iOS 输入缩放 | ✅ | 输入框字号 ≥16px，避免 iOS Safari 自动放大页面 |

## 二、移动端的硬性约束（必须提前知道）

### 1. 摄像头必须 HTTPS

`getUserMedia` 只在**安全上下文**可用：

- ✅ `https://xxx.com`
- ✅ `http://localhost:3000`（仅限本机）
- ❌ `http://192.168.1.5:3000`（手机访问电脑局域网地址 —— **最常见的踩坑点**）

因此：**用手机测试人脸登录，必须先给服务配 HTTPS**。当前 `face.js` 已在检测到非安全上下文时
给出明确提示并引导改用口令登录，不会让用户对着失败的摄像头发呆。

自测方式（无需正式证书）：

```bash
# mkcert 生成本地证书，然后：
node server.js   # 改用 https 启动，或在前面挂一层 nginx / caddy 反代
```

### 2. iOS Safari 的限制

- 必须由**用户手势**触发（点击「开启摄像头」按钮），不能自动开始
- 视频必须 `playsinline` + `muted`，否则强制全屏
- 后台切回时摄像头流会中断，需要重新开启（已用 `visibilitychange` 处理会话恢复）

### 3. 移动端人脸采集的质量问题

手机前置摄像头多为广角、分辨率高、噪点大，且孩子移动频繁。
因此注册时采集 **3 张不同角度**（`FACE.describeMulti`），登录时跨样本集取最小距离 ——
实测这把「同一人」的距离从 0.334 压到 0.219，与「异人」的间隙从 0.03 扩大到 0.116。

## 三、路线选型（后续真正要做移动端时）

### 方案 A：PWA（已实现，成本最低）

**适用**：先让手机浏览器能用，不急于进应用商店。

- 现状已完成，只需补：推送通知、更细的离线缓存策略调优
- 优点：一份代码，iOS / Android / 桌面通吃；更新即时生效
- 局限：无法调用系统级能力（如 Face ID Touch ID、系统级活体检测）；iOS 推送需 16.4+ 且要装到主屏

### 方案 B：微信小程序（推荐给「家长」场景）

**适用**：家长用户占多数、需要微信通知、孩子用家长手机扫码学习。

- 复用现有全部后端 API，只需重写前端层（小程序不支持 DOM）
- **人脸登录**：小程序有 `wx.createFaceAuth` / 云开发的人脸核身能力，
  但**需要小程序类目资质**（教育类目 + 人脸核身权限），个人主体无法申请
- 降级路径：小程序内 `wx.chooseMedia` 拍照 → 传本服务提取特征 → 匹配（当前方案可直接复用）
- **注意**：小程序要求 HTTPS 域名备案，且需在小程序后台配置 request 合法域名

### 方案 C：原生 App（iOS + Android）

**适用**：需要 Face ID / 系统活体检测、离线能力、或要做应用商店分发。

- 人脸识别可直接调用系统能力（Face ID / Android BiometricPrompt），比自建特征匹配更安全
- 推荐技术栈：Flutter（两端一套代码）或 React Native（与现有 Web 技术栈接近）
- 需要新增：原生端的人脸特征与 Web 端**不通用**（不同模型），
  建议服务端支持**多套特征源**，或原生端把特征上传到同一服务但用不同命名空间

### 推荐路径

```
当前（Web 响应式 + PWA）
   ↓  家长和小先用起来，验证留存
小程序（家长侧：微信通知、扫码登录孩子账号）
   ↓  需要系统级人脸/生物识别时
原生 App（可选，仅在确有需求时做）
```

## 四、用户体系在移动端的注意事项

这部分已在代码中处理，是后续做 App 时不需要改的地方：

| 设计 | 原因 |
|---|---|
| 令牌走 `Authorization: Bearer` 头，不用 Cookie | 小程序 / 原生 App 都不方便带 Cookie |
| 人脸特征在**客户端**提取，只上传向量 | 移动端算力足够，且避免上传原图（隐私合规） |
| 家庭（family）是登录的单位 | 家长用一个账号管理多个孩子，符合实际家庭结构 |
| 学生也可用人脸登录 | 孩子自己拿手机就能进，不需要家长在旁边配合 |

## 五、公网部署的额外要求（移动端访问的前提）

当前服务默认绑定 `127.0.0.1`，手机访问不到。公网部署需要：

1. `HOST=0.0.0.0`
2. `ADMIN_TOKEN=...`（管理接口必须鉴权）
3. `CORS_ORIGINS=...`（或保持同源部署，避免跨源配置）
4. **HTTPS 证书**（人脸功能的硬性要求）
5. `REDIS_URL=rediss://:密码@xxx.redis.tencentcloudapi.com:6379/0`（云端 Redis）
6. 限流阈值按实际用户量调整 `RATE_LIMIT_PER_MIN`

## 六、已实施的移动端细节

以下改动集中在 `pwa.js` / `pwa.css`，与主界面样式解耦，不影响桌面观感
（`env(safe-area-inset-*)` 在浏览器标签页下恒为 0，只有装到桌面独立窗口时才有实际数值）。

### 1. 安装引导（`pwa.js`）

- 只在**窄屏**（≤820px）出现，桌面浏览器自带安装入口，弹窗只会变成打扰；
- 捕获 `beforeinstallprompt` 后按钮可直接调起系统安装；
- 没拿到安装事件时（iOS Safari、部分安卓浏览器），改为给出各平台的手动添加步骤；
- 提示条放在**顶栏下方**而不是底部 —— 右下角是 IP 形象挂件的位置，两者会打架；
- **不能压住顶栏**：顶栏右侧是身份入口（登录 / 注册），提示条一旦盖上去，
  手机上就再也点不到登录按钮（曾真实发生过）。现在它定位在顶栏下方，
  并由 `test:ui` 断言「安装引导不遮挡身份入口」；
- **弹窗打开时自动隐藏**：提示条是 `fixed` 定位，压在模态层上方会挡住弹窗标题与按钮。
  用 `MutationObserver` 监听 `modal-backdrop` 的 `hidden` 属性，弹窗开时收起、关时补回；
- 视口在宽窄之间切换时自动收起/补显，用户手动关闭后记入本地存储不再打扰。

### 2. 版本更新提示

Service Worker 检测到新版本时，不静默替换（否则用户正在看的页面会被换掉），
而是提示「知岛更新好了 → 立即刷新」，确认后通过 `SKIP_WAITING` 消息让新版本立即接管。

### 3. 安全区域

顶栏、侧边栏、页面底部、IP 挂件、Toast 全部套上 `env(safe-area-inset-*)`，
刘海屏与 Home Indicator 下都不会遮挡内容。

### 4. 触控尺寸

移动端把主要可点元素（开始讲解、身份入口、分享/收藏、图标按钮、快捷标签等）
的触达区统一抬到 ≥40px，同时保持视觉尺寸不变；
输入框字号 ≥16px，避免 iOS Safari 聚焦时自动放大整页。

### 5. 回归测试

`npm run test:ui` 用真实浏览器覆盖以上各项：

```
[移动端 390px]  无横向溢出 / 顶栏单行 / 触控区 ≥40px / 输入框 ≥16px / 弹窗不溢出
[PWA]           manifest 可读 / SW 已注册 / 安装引导出现 / 不遮挡 IP 挂件 / 桌面端不打扰
```

服务需先启动（`npm start`），测试默认访问 `http://127.0.0.1:3000`，
可用 `UI_TEST_URL` 环境变量指定其他地址。
